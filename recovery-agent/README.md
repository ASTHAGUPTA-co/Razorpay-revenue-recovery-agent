# Revenue Recovery Agent
Razorpay AI Buildathon — Track 3: AI Revenue Recovery

An agent that watches failed payments, diagnoses the root cause with an LLM,
picks ONE action from a fixed/bounded list, executes it (real Razorpay
test-mode payment link, or a drafted Hinglish nudge), and logs everything to
an auditable trail. Dashboard shows measured recovery rate, money recovered,
and an honest list of cases it couldn't fix.

## Architecture

```
Failed Payment (synthetic or real webhook)
        │
        ▼
 AI diagnosis (Claude API, strict JSON output)
        │
        ▼
 Bounded action gate  →  retry_link | whatsapp_nudge | escalate_human | no_action
        │
        ▼
 Execute (Razorpay test API / draft message)  →  Log to RecoveryLog (audit trail)
        │
        ▼
 Dashboard: recovery rate, ₹ recovered, exception list
```

- **Backend:** Node + Express + MongoDB (Mongoose)
- **AI:** One Claude API call per payment, forced structured JSON output,
  clamped to a fixed action set in code (not just prompt-level)
- **Payments:** Real Razorpay test-mode Payment Links API
- **Frontend:** React (Vite) — queue view, per-case audit trail, metrics panel

## Setup

### 1. Backend
```bash
cd backend
npm install
cp .env.example .env
# fill in MONGO_URI, RAZORPAY_KEY_ID/SECRET (test mode), ANTHROPIC_API_KEY
npm run seed     # generates 60 synthetic failed payments
npm run dev      # starts on :5000
```

### 2. Frontend
```bash
cd frontend
npm install
npm run dev       # starts on :5173, proxies /api to :5000
```

Open http://localhost:5173, click **"Process all failed (batch)"**, and
watch the agent diagnose + act on every payment in the queue.

## Guardrails implemented
- Fixed action set — model output is clamped in code even if it misbehaves
- Max 3 recovery attempts per payment before forced escalation
- High-value payments (>₹50,000) always escalate to a human regardless of
  model confidence
- Every decision + execution result is logged, forming a full audit trail
- Unparseable AI responses fail safe (escalate), never guess with money

## Notes
- WhatsApp messages are drafted and logged, not actually sent (would need
  WhatsApp Business API approval) — this is a reasonable, clearly-stated
  demo scope limitation, not a hidden gap.
- All payment data is synthetic, generated by `backend/scripts/seedData.js`.
